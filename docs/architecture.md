# Architecture and safety boundaries

The workspace separates `profiler-core` (safe Rust measurement aggregation and report serialization) from `php-profiler` (ext-php-rs runtime API and Zend lifecycle adapter). The C bridge contains version-sensitive Zend observer registration, clock/heap reads, fiber callbacks, and allocating Zend calls that require C-owned bailout boundaries. It does not implement profile aggregation or persistence. Within `profiler-core`, `lib.rs` owns the measurement engine, report data and availability rules; private `serialization.rs` owns JSON encoding, the accessor-size bound and atomic filesystem publication. Private `budget.rs` and `storage.rs` own shared admission accounting and fallible bounded buffers; private `index.rs` owns preallocated, append-only symbol and edge lookup tables. Hashes are lookup hints and full key equality determines identity. Output code borrows the report and does not access live engine or Zend state. PHP methods and the report schema remain stable; Rust container types and the JSON return buffer now carry allocation ownership explicitly.

Request/thread-local state owns sessions and frame identities. Public session IDs are positive, unique and increasing within a request; IDs restart for the next request. Borrowed Zend frame, function and name descriptors are read only within their callbacks; retained frame identities remain opaque. The optional native sampler also retains the owning request’s `EG(vm_interrupt)` atomic and stores to it from its timer worker. An actual successful join must precede retirement of that executor storage, native control object or extension code. Closure identities use a public Zend runtime-cache extension word and a process-wide, nonwrapping identifier sequence. This distinguishes newly compiled closures even when Zend reuses freed addresses. Instances sharing a compiled factory cache aggregate together; bindings with distinct runtime caches remain separate. Request shutdown finalizes retained sessions and resets state before a reused worker handles another request. Session handles identify one request-local record; reset invalidates retrieval through that handle. Concurrent processes publish reports independently and cannot replace an existing report at the same path.

Fiber destruction distinguishes active measurements, retained context identity cleanup, and an untracked disabled request. The last case reads no clocks or Zend heap counters and does not enter Rust. Cleanup of completed records removes identities without creating measurement boundaries; an interrupted, unsealed capture receives genuine observations when needed. Directory publication reuses the first stop timestamp, so unrelated clock failures after sealing cannot poison a later capture.

The installed observer has a native disabled gate before crossing into Rust. PHP controls capture state; loading the extension does not automatically start a session. Observer failures and unavailable clocks make a report incomplete rather than fabricating successful measurements. Infrastructure failure flags remain sticky within the request until explicit reset of all retained state; retaining a damaged trace does not silently restore trustworthy capture. Rust panics must be contained at exported callback boundaries. Allocating Zend API calls must remain inside documented C bailout guards; unwinding or longjmp across live Rust owners is unsafe.

The engine uses explicit clocks and heap observations, making arithmetic and exceptional paths testable without PHP. It fallibly preallocates indexed symbols, edges, timeline records and a frame pool shared by every fiber; instrumentation boundaries allocate no heap storage. Report materialization uses separate charged ownership and preserves finalized capture if admission fails, allowing a retry without changing the stop snapshot. The adapter freezes the first stop boundary, termination reason, native failure flags, request heap peak and bounded execution metadata before materialization. Sealed engines stop receiving observer events; subsequent application execution cannot change their retry result. Fiber switches segment active time so another fiber's execution is not attributed as active child CPU. Recursion remains explicit in frame stacks and self-edges. Generator observer events describe resume segments rather than guaranteed logical generator invocation counts.

`max_events` bounds stored symbols, edges, active frames and timeline records, not the total number of repeated calls that may be aggregated. Timelines are opt-in. Graph recording continues after timeline capacity is reached; the report separately discloses dropped timeline events. Request limits, JSON accessor limits and explicit truncation keep resources bounded. Reports distinguish capability/provenance declarations from measurements.

Runtime payload privacy is deliberate: SQL/HTTP/I/O categories recognize supported internal call symbols without inspecting arguments or response values. Generated closure and anonymous-class names use opaque identities to avoid embedded source paths. No collector, socket listener, HTTP client, telemetry or external agent belongs in the profiler runtime. Loopback HTTP servers and SQLite used by tests are fixture infrastructure only.

Extension load compatibility requires matching PHP headers, ABI and NTS/ZTS builds. A supported-version claim needs passing real PHP matrix evidence, not a successful Rust compile. JIT and OPcache behavior must be tested with their runtime status recorded; merely setting configuration flags does not prove they remained active.

The [unsafe integration inventory](unsafe-inventory.md) records callback ownership, C bailout guards, dependency constructor/exception boundaries and retained-memory formulas. The [core memory budget](core-memory-budget.md) describes implemented fallible requested-capacity accounting and allocator-ledger tests. Extension-wide verification must account for adapter storage, output overlap and any standard-library scratch allocations; a core-only result does not establish a total process-memory bound. Allocator bookkeeping and returned PHP values are explicitly separate from native requested capacities, without optimistic per-record estimates.

Opt-in sampling adds two cohesive boundaries: `sampling.c` owns the bounded wall
worker, tick queue, Zend interrupt chaining and native lifecycle; adapter
`sampling.rs` copies callback-lifetime stack descriptors into an independent,
preallocated core sampler. The worker never calls Zend, PHP or Rust; only the PHP
thread reads execution frames. Sampling and function instrumentation have separate
symbol capacities and failure states. Counter baselines and final snapshots use
the producer-locked monotonic clock; stopping several sessions freezes every
measurement before serialization or joining. Version 2 reports preserve sampling
losses and safepoint bias explicitly. Successful joins precede native resource
retirement; ordinary unsampled sessions start no worker. See
[sampling semantics](sampling.md) and [lifecycle evidence](sampling-validation.md).
